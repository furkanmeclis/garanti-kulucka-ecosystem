# ADR 0004: Database Access And Migrations

## Status

Accepted

## Decision

Use Kysely for application query building and node-pg-migrate for production migrations.

## Rationale

The project needs explicit PostgreSQL control, stable migration files, and strongly typed query composition without tying business logic to ORM models.

Kysely keeps application queries typed while staying close to SQL. node-pg-migrate keeps schema evolution migration-first and reviewable.

## Consequences

- Application code imports repository ports and Kysely-backed adapters, not migration files.
- Migration files are frozen history and must not depend on current application types.
- Migrator may use raw SQL/Kysely readers and writers, but migration execution remains separate from the API.
- Production schema changes are not generated by app startup or ORM auto-sync.
